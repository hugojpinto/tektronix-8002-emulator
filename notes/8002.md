# 8002A mainframe: System Processor, memory, Debug module

Facts as modelled in `emu/src/machine/tek8002.*` and `tek8002_debug.*`. Sources:
the service manual 070-2711 (1981 edition, `sources/bitsavers/manuals/800x/`), the ztpe.nl
"OS Reference and Internals" draft of 2026-07-10 (`sources/ztpe/osinternals.pdf`,
Annex B "IO ports", chapter 8 "Debugging"), and TekDOS 3.3 itself.

## Clock
The 2650 runs at 10 MHz ÷ 8 = 1.25 MHz (070-2711 §3, "2650 Clock Logic"). A separate
9.984 MHz oscillator drives the baud-rate chain (38.4 kHz = 16 × 2400 baud, the I/O clock
on the backplane) and the interval timer (Fig. 3-2).

## Memory (070-2711 §3 "Program Memory Bank Select Logic", §4)
| 2650 address | What |
|---|---|
| 0000–00FF (reads) | bootstrap PROM, overriding the RAM (§4 "Bootstrap PROM"). Writes go to the RAM underneath |
| 0000–3FFF | System Memory, 16K |
| 4000–7FFF | one 16K bank of Program ("common") memory, selected by port EE bits 1–0 |

The 8002A has two program memory boards as standard, up to four. TekDOS 3.3 sizes and
clears all four banks at start-up (1D62–1D86: it reads and rewrites every byte, which
initialises parity). A bank with no board reads FF here (*inferred*; the parity error
interrupt is not modelled).

## Interrupts (Table 3-1)
Vector address 2n for interrupt n, priority n (0 highest). During INTACK the vector
generator puts 2n on the bus. The 2650 performs a direct ZBSR to page-zero address 2n,
where the bootstrap PROM branches indirectly through its table at 0040+2n to a 3-byte
slot in RAM at 1000+3n. TekDOS fills those slots in.

| n | vector | function | modelled |
|---|---|---|---|
| 0 | 0000 | reset | — |
| 1, 3 | 0002, 0006 | system / program memory parity error | no |
| 4, 5 | 0008, 000A | console in (DA) / console out (TBMT) | yes |
| 6–8 | 000C–0010 | System Communications 1–3 | no |
| 9 | 0012 | interval timer | yes |
| 11 | 0016 | Flexible Disc (FLAG going low: the end of an operation, `notes/fdc.md` stage C) | yes |
| 13, 14 | 001A, 001C | PROM programmers | no |
| 16–23 | 0020–002E | emulator SVCs (slave writes F0–F7) | no |
| 24, 25 | 0030, 0032 | breakpoints | no |
| 26 | 0034 | single cycle | no |
| 27 | 0036 | slave halted | yes |
| 28 | 0038 | diagnostic (front panel) | no |
| 29 | 003A | RTPA | no |

**Disc interrupt = 11.** The OCR text of Table 3-2A (both the 1979 and 1981 editions)
places the disc and printer flip-flops at "INT 31" and "INT 30". Table 3-1 says 11, and so
does TekDOS 3.3's jump table: slot 1021 (vector 11) goes to its disc handler 25AF, while
slots 105A and 105D (vectors 30, 31) go to a bare `RETE` at 2F25. Established by running
TekDOS: with the flip-flop at 31 it ignores the interrupt and LDIR hangs; at 11 it works.

The interrupt flip-flops are edge-triggered and are reset as their vector is taken
(§3 "Interrupt Vector Decoder").

## I/O ports of the System Processor (Tables 3-4 to 3-8)
| Port | Read | Write |
|---|---|---|
| E8 | console data (resets DA) | console data |
| E9 | UART status: 0 DA, 1 TBMT, 2 overrun, 3 framing, 4 parity | serial control: 0 reader on, 1 even parity, 2 TTY interrupt enable |
| EA | 7 FLAG, 6 tape, 1 printer fault (active low), 0 printer busy (active low) | 5 printer int enable, 4 disc int enable, 2–0 C1 C0 /S (`notes/fdu.md`) |
| EB | disc data / status byte | disc data |
| EC | — | 0 timer interrupt enable |
| EE | — | 1–0 program memory bank |

Table 3-4 names the write decoder's outputs TINT and BNK for EC and ED. Table 3-8 and
TekDOS (1D67, 3AF2) put the bank switch at **EE**.

The console UART is an AY-5-1013 with only RxD/TxD wired (every RS-232 control line is
tied high on the board: §3, confirmed on a real board in the EEVblog thread, post #35).
The baud rate is a thumbwheel, 110–2400 (Table 3-7). The emulator paces characters at
2400 baud.

The interval timer gives 10 ms or 100 ms (jumper). TekDOS 3.3 does not enable it at
start-up.

## Debug and Front Panel I/O module (§6)
| Port | Write | Read |
|---|---|---|
| F8 | debug control, active low: 0/1 BP1 read/write, 2/3 BP2 read/write, 4 single cycle, 5 debug enable | — |
| F9 | command, active low: 0 forced reset, 1 forced interrupt, 2 forced jump (each write with the bit low arms it for the next hand-over), 3 interrupt mask, 4 SVCs disabled | — |
| FA/FB | forced jump address, inverted | — |
| FC/FD | breakpoint 1, inverted | **PC next**, true |
| FE/FF | breakpoint 2, inverted | **PC last**, true |

Table 6-1A names F8 "command byte" and F9 "debug control byte", but the text, Figs. 6-1/6-2
and ztpe.nl say the reverse. TekDOS writes F9 ← FA (forced reset + forced jump) before
starting a slave, which fits the text.

**Master/slave hand-over.** The master gives the bus to the active slave by executing HALT. If
no slave takes the bus within one 38.4 kHz I/O clock, the slave halt detector sets and the
module raises interrupt 27, which wakes the master (§6 "Master/Slave Halt Detection").
TekDOS 3.3 (6800 disc) relies on this at start-up: it activates the 6800 emulator slave
(port E2 ← 90), points the forced jump at F9FA (the board's register restore routine) and
HALTs at 1DC1, ten times (1D9C–1DD3). With no emulator board fitted, interrupt 27 arrives,
and TekDOS turns the slave off (E2 ← 00) and carries on to its banner. With the board, each
try ends in its debug SVC (interrupt 22; `notes/emulators.md`). Established by running it: before
interrupt 27 was modelled, TekDOS stayed halted at 1DC1.

**Slaves and the debug interrupts** (`tek8002_debug::run_slave`, the same for every slave board):
- The active slave runs while the master is halted, and is paused whenever an interrupt for the master is pending.
- **SVC:** a slave OUT to F7 … F0 raises interrupt 16 … 23 (F7 = SVC 1; ztpe.nl §8.2.1). It only pauses the slave, which continues after its OUT when the master halts again. Established by running ASM: TEKDOS's SVC handler never rewrites the jump address, so a forced jump armed by the SVC would restart the Z80 at 0000. That made ASM loop forever on its first SVC. ztpe.nl §8.2.2 says the Debug card arms a forced jump whenever it raises an interrupt, which holds for the others (breakpoints, single cycle, halt), where the master sets the address.
- **Forced reset and forced jump:** every write of F9 with the bit low arms one, and the next hand-over to the slave takes it. §6 "Forced Jump Logic": the command byte sets the Forced Jump Enable flip-flop, and the master's halt clocks the jump command out. TEKDOS's 6800 probe depends on it: each of its ten tries writes F9 ← FA again without writing a 1 in between (1D9C–1DC1). ztpe.nl reads it as a 1 → 0 transition, which software that writes the bits back to 1 cannot tell apart. TEKDOS writes FB:FA = FFFF (0000, inverted) and F9 ← FA before starting the assembler.
- **PC last and PC next** (§6 "Program Counter Registers"): FC/FD read PC next and FE/FF PC last, both true, and they follow the slave's fetches only while debugging is enabled (F8 bit 5 low; ztpe.nl). Established by TEKDOS's debug control (DEB CNTL 1589–15CF): FD/FC becomes the resume address and DSTAT's P=, FF/FE the trace line's LOC, and both are used as read. ztpe.nl (the Signetics TWIN) has the opposite pair, inverted. The emulator's dump routine runs with debugging off, so it does not replace the user's PC. Checked by a TRACE ALL of a 6800 program (`tests/run6800.sh`).
- **SVCs are enabled while F9 bit 4 is high.** Fig. 6-1's OCR text says "Service Call Enable = 0", ztpe.nl says "service calls disabled" when low. TEKDOS writes FA (bit 4 high) and then relies on SVCs, which fits ztpe.nl.
- **Breakpoints** (24/25): the slave's read (instruction fetches included) or write of the breakpoint address, as F8 bits 0–3 enable it (active low), while F8 bit 5 (debug enable) is low. They take effect after the instruction. **Single cycle** (26): after every instruction while F8 bits 4 and 5 are low. Both arm a forced jump, like a halt (070-2711 §6, ztpe.nl §8.1.5/8.2.1).
- **Interrupt mask** (F9 bit 3 low): debug interrupts are held and raised when the mask is released (§6 "Interrupt Mask Bit": "allowed to stack"). Checked by `emu/tests/debug_test.cpp`, and breakpoints and single cycle by TEKDOS's DEBUG on the 6800 board (`tests/run6800.sh`).
- **DIAG INTRPT** (28): the front panel switch (the monitor's `D` command).

**Front panel lamps** (070-2711, 1981 edition: schematic 9 "Standard Front Panel", A40 Lower
Front Panel board, PDF p. 309; schematics 4A/4B, Debug and Front Panel I/O, PDF pp. 290–291;
the 1979 edition has the same circuit on PDF p. 230). Each lamp is a pair of red LEDs from
+5.2 V through 220 Ω, lit when its cathodes are pulled low. Read from the schematics:
- **PWR** (DS1146/1147): cathodes tied to ground. Lit whenever +5.2 V is present.
- **SYS** (the pair labelled MASTER, DS1086/1087): lit while the MSTR/SLV flip-flop (U2150A on
  A5, the master/slave hand-over of §6) gives the bus to the System Processor. Its Q̄ (SLV) is
  inverted by U1130C and sent on P3-9 to a 7406 on A40 that sinks the cathodes. A second pair,
  SLAVE (DS1096/1097), lights exactly when MASTER does not. *Inferred:* that the SYS legend
  sits over the MASTER pair (070-2701 Fig. 2-6 names SYS, RUN, PWR; the troubleshooting step
  ties SYS to the Debug and Front Panel I/O module). What legend, if any, sits over SLAVE is
  not known.
- **RUN** (DS1126/1127): lit while the bus line RUN is active (a processor runs; RUN-bar
  inverted by U1110A on A5) **and HOLD is not** (HOLD-bar inverted by U1130 on A5; on A40 an
  8T98 gate enabled by RUN and fed by HOLD inverted). So RUN goes dark while the bus is held.
The emulator follows this: SYS from the master/slave state, RUN from a processor running
(it has no bus hold, so HOLD never darkens it), PWR from power. Holding SYSTEM RESTART
darkens SYS and RUN in the emulator; what the restart does to these lines is not shown
(inferred).

## Assembler Processor (670-5220; 070-2711 §9)
A Z80 at 2.5 MHz (10 MHz ÷ 4) running TEKDOS's assembler and linker from program memory (`tek8002_asmproc`). TEKDOS loads the tool, writes FB:FA, F9 ← FA, E2 ← 02 (6800 board off), **E7 ← 90** (Active, bit 7; §9: becoming active resets the Z80 to 0000), F8 ← FF, C3 ← 0E, and HALTs (TEKDOS 3.3, 395F–399B).
- **Memory:** program memory as one linear space, board = A15–A14 (two boards: 0000–7FFF; reads above give 00, the open bus).
- **I/O:** only the SVC ports are seen (OUT F0–F7); `-io` logs anything else as unmapped.
- **Established** by TEKDOS 3.3's ASM and LINK on a 6800 source (`tests/asm_link.sh`): 120 SVCs for a 10-line module, "No assembly errors detected", a listing with correct 6800 code, and a linked load file holding the same bytes.

## System Communications (670-5219; 070-2711 §5)
Three MC6850 ACIAs and the memory map (`tek8002_syscomm`). TEKDOS reaches them at **C9–CF**: it master-resets the ACIAs with 03 at CA, CC and CE (1D18–1D1E), and loads the map at C9. The manual's Tables 5-2/5-3 number them F9–FF, with the same low nibble.

| Port | Device (Table 5-1) | TEKDOS name | Interrupt |
|---|---|---|---|
| CA/CB | J101 modem | REMI / REMO | 6 |
| CC/CD | J102 line printer | LPT1 | 7 |
| CE/CF | J103 paper tape reader/punch | PPTR / PPTP | 8 |

- Even ports are control/status, odd ports data (Table 5-4). Baud rates are jumpers (110–2400), modelled at 2400.
- **The ACIAs' IRQs are levels.** The interrupt is pending exactly while an IRQ is asserted. A request the ACIA withdrew before INTACK is not taken. Latched as an edge, a stale INT 7 made TEKDOS's printer driver write into a full transmit buffer and lose every other character.
- **The transmitter is double-buffered**, as on the MC6850. TEKDOS's printer driver writes ahead, a second byte while the first is still shifting out (`machine/mc6850.h`).
- **Memory map:** 512 bits, one per 128-byte block of an emulator's 64K. It is loaded and read one bit (D0) at a time at C9 through an auto-incrementing counter (§5 "Memory Map Address Logic"). TEKDOS writes 02 and then 512 bytes, so a write with D1 set is taken as the counter reset (*inferred*). No prototype exists yet to use it.
- **Established** by TEKDOS 3.3 (`tests/syscomm.sh`): LDIR to LPT1, and COPY of a source file to REMO and to PPTP, each byte for byte.
- **Open: REMI and PPTR input.** A line sent by a host arrives intact. When a second line follows without a pause, TEKDOS discards it while it files the first, at the console (CONI) as well. On the console it sends DC3 (Teletype "reader off") after each line, which suggests the sender was expected to pace itself. No handshake has been seen on REMO yet.

## The open bus: reads where no board answers give 00
The boards drive the backplane's data bus through inverting buffers (§9 "Address and Data Bus
Buffers": "the data transferred through these buffers is also inverted"). A line nobody drives
floats high and reads as logic 0. TEKDOS relies on it: its debug control takes port C2 reading 0
as "no trace board" and then uses the Debug module's PC registers (DEB CNTL 157E). With FF there,
it took the trace board's C4–C7 instead, and every trace line read LOC 0000. This applies to
absent ports, and to program memory above the boards fitted (2650 and slaves).
