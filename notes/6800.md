# The 6800 Emulator Processor

`emu/src/machine/tek8002_ep6800.*`: a 6800 (MAME's core, `emu/src/cpu/m6800`, generated by
`tools/port_m6800.py`) at 1.00 MHz (1978–81 catalogues) that runs the user's program from
program memory as a slave of the System Processor. The board's two PROMs (82S115 "SYSTEM" and
"FETCH") are not preserved; what they do is modelled from the manuals and from what TEKDOS 3.3
does around them. The board's own service manual ("8002 µProcessor Lab 6800 Emulator Processor
Service Manual", 070-2701 lists it) is not on bitsavers.

Sources: 070-2349 (6800 Assembler and Emulator Users Manual) §10–11; 070-2711 §1 ("Emulator
Processor Module" and the debug-mode walkthrough, steps 1–41) and §6; ztpe.nl §8 (the same
Debug card under Signetics' DOS); TEKDOS 3.3's kernel and its overlays in `.` (DEB INIT, DEB
CNTL, DSTAT, TRACE PRINT). The overlays are MOD modules, each starting on a sector with its own
header and load address (DEB CNTL at 1500, the others at 1880).

## What TEKDOS needs of the board
| Item | Behaviour | Established by |
|---|---|---|
| Control port | E2 (TEKDOS's emulator table at 2032/2033). Bit 7 = active. Values seen: 90 (start-up probe), 92, 96, 80 or C0 (starting a traced program, from the emulation mode), 00 (off). The other bits are recorded, not decoded | `-io` logs; DEB CNTL 160E–1619 |
| Status | read at E2. Normal: bit 7 high, bit 4 low (0xEF modelled; other bits unknown). Bit 7 low or bit 4 high makes TEKDOS treat the last instruction as incomplete: resume at PC last and reset the board | DEB CNTL 1550–155C, 15A9–15BB, 1602–1607 (*inferred meaning*) |
| SVCs | a read or write of FEF7–FEF2 is SVC 1–6 (the Debug module's ports F7–F2); FEF1/FEF0 are its F1/F0. Pointers to the SRBs at 0040–004B. The access does not reach memory, and an instruction makes one SVC | 070-2349 §10, Table 10-1; a program printing by SVC 1 and exiting by SVC 2 (function 1A) |
| Halt | WAI. Outside DEBUG TEKDOS reports `*DOS* ERROR 46` (emulator halted); inside, a break at the WAI, and GO continues there | 070-2349 §11 ("WAIT"); TEKDOS booklet error 46 |
| Forced jump | replaces the next fetch with a jump (here: sets the PC). It also ends a WAI | 070-2711 §6 |
| Restore routine | **F9FA**: loads A, B, X, SP, CC from 0000–0006, then the debug SVC 1 (port F1, interrupt 22), then waits in the PROM for the next forced jump | 070-2711 §1 steps 9–19; TEKDOS forces a jump to F9FA before GO and in its start-up probe |
| Dump routine | **F9FD**: stores A, B, X, SP, CC at 0000–0006, then the debug SVC 1, then waits | 070-2711 §1 steps 34–37; TEKDOS forces it after every traced instruction and breakpoint |
| Register area | 0000 A, 0001 B, 0002–0003 X, 0004–0005 SP, 0006 CC. TEKDOS swaps these seven bytes with its own buffer (1538) around each call, so the user's bytes are kept; DSTAT and SET work on the buffer | DEB CNTL 1733–174B; DSTAT 18E9–1937 |

The entry points come from DEB INIT (195D–196E), which stores F9FA and F9FD for DEB CNTL, and
from the start-up probe's table (24CB: F9 FF, minus 5). No 6800 code on the system disc touches
FEF0–FEF7, so the dump and restore code is the board's own, as 070-2711 §1 says ("a PROM to hold
a dump and restore routine").

## Modelled at high level
- The two PROM routines run as one step each; their timing is a guess (35 cycles). The real
  routines must disturb nothing but 0000–0006: how the PROM saved CC without changing it is not
  known, and the model saves the true CC.
- The PROM is reached only by fetches at F9FA and F9FD. Where the PROM sits in the 6800's
  address space, and whether it hides program memory there, is not known.
- Mode 0 only (program memory). Modes 1 and 2 need a prototype and the board's probe.
- The forced interrupt (F9 bit 1) is not used by TEKDOS.

## Found in the Debug module and the mainframe while doing this (`notes/8002.md`)
- A forced jump or reset is armed by each write of the command byte, not by a 1 → 0 edge (the
  start-up probe retries with F9 ← FA ten times).
- FC/FD read PC next, FE/FF PC last, true; they follow the slave only while debugging is enabled.
- Reads where no board answers give 00 (inverting bus buffers): TEKDOS tests port C2 for zero.

## Checked (`tests/run6800.sh`, in `make test`)
ASM, LINK, LOAD and GO of `tests/data/run68.s`: the 6800 sums its message (04C4, the right sum),
prints it by SVC 1 and exits by SVC 2. Under DEBUG: TRACE ALL gives the manual's trace line for
every instruction (20 loop passes, flags as computed); a read breakpoint stops after its
instruction; DSTAT shows the registers; SET changes them and GO uses them (the stored B); TRACE
STEP; WAI as above. Both disc models.
