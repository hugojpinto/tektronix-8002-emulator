# Tektronix 8002A µProcessor Lab emulator

This project emulates the **Tektronix 8002A µProcessor Lab** (1978–79): the mainframe with a Signetics 2650 System Processor, the Flexible Disc Unit and any RS-232 terminal, running TEKDOS. The 8002 is the Millennium Universal One / Signetics TWIN, rebadged; the 8002A is an 8002 with a second program memory board.
It is the sibling of `../tektronix-8550-emulator` (the Tektronix 8550 emulator, called MDL in these notes) and follows the same design, conventions and working method. The emulator is standalone C++17. Its 2650 and Z80 cores come from MDL (originally MAME, BSD-3, and superzazu/z80, MIT), and the code is structured so it can be upstreamed into MAME later.

Start with `FEASIBILITY.md` (what survives, the plan), then `notes/` (hardware facts).

## Resuming work (state on 2026-11-15)
**Z80 board firmware rebuilt and running** (2026-11-15): never dumped, but Millennium's Z80 DEBUG diagnostic (DE310, DIP 4.4 disc in `sources/bitsavers/disks/Millennium_internal_floppies/`) carries a table that becomes the firmware with a byte inserted before every xxx0 address and the frame shifted (why it differs so is open: a faulty copy, or a PROM view not modelled; whether a real board passes subtest E is unknown). `tools/rebuild_z80_firmware.py` → `roms/epz80/z80_firmware.bin` (1K, F800-FBFF; 35 bytes by reasoning, `--report`). It runs on the Z80 (`-epz80 hle` keeps the model, aligned to it). It showed: the forced jump is a jammed JP (an M1 cycle, R+1); a halted Z80 ignores it (TEKDOS uses NMI + jump, NMI first); block byte 1A is added to SP by the dump (TEKDOS sets 2 after a halted-board break). Boards' PROMs answer the System Processor's program-memory reads while mapped. Open: the table at F900 (DE310 subtest F, instruction decode); modes 1/2 steering is inferred (data cycles outside 0000-001F go to the prototype).
**Diagnostics** (2026-11-15): DIP 4.4 runs (`notes/diagnostics.md`, `tests/dip.sh`, 13 modules pass). Findings shared with the 8550 are in its ROADMAP, "To verify".
**8080A board done, with its PROMs** (2026-11-13): `tek8002_ep8080` (E1) on the i8085 core in 8080 mode (`cpu/i8085`, copied from the 8550, flag marked [tek8002]). P1 = Intel MDS-800 monitor interface (as read); P2 = SVC templates, assembler patches and debug firmware, **rebuilt** by `tools/rebuild_8080_p2.py` because Eelco's chip lost data bit 0 (every restored bit listed with a confidence; `--report` for the table). `tests/run8080.sh` (15) and `tests/prototype.sh` (+7) verify everything TEKDOS uses; FA40–FB20 (patches for an unpreserved assembler) is reasoned only. Eelco offered to burn a new P2 from the rebuild.
**6800 board PROMs dumped and running** (2026-11-13): Eelco Vriezekolk sent SYSTEM and FETCH (`roms/ep6800/`). SYSTEM runs on the 6800 at F800–F9FF; FETCH's bits 7/6 steer the firmware's PSHA/PULA cycles to 0000 and its indexed LDA/STA to the prototype (*inferred*, `notes/emulators.md`). `-ep6800 hle` keeps the old model. The 6800 core's TAP/RTI now keep CC bits 7–6 ([tek8002]).
**Version 0.9.0 released** (2026-11-12; public at github.com/hugojpinto/tektronix-8002-emulator): `VERSION` is compiled into every program (`-version`), and `host/paths.*` finds `roms/` and `artwork/` beside the program. **Step 5, the disc controller at low level (070-2587):** stage A (microcode, `roms/fdc`, `tools/fdc_dasm.py`) and stage B (the processor, `tek8002_fdc.*`, `emu/tests/fdc_test.cpp` in `make test`), stage C (flux-level tracks `tek8002_fdd.*`, reads) and stage D (writes, FORMAT) are done: the real controller is the default, `-fdc hle` keeps the high-level model, and the session tests run in both (`FDC=hle tests/...`). `notes/fdc.md` records the facts. Lamps SYS/RUN are inferred. Next (ROADMAP step 7): options (PROM programmers, RTPA), the 8080 board.

**How hardware is reverse-engineered here:** read the service manual's theory of operation and schematics, then let TEKDOS show what it does: `-io` logs every port access, `-trace` every instruction, `TEK_INTTRACE` every interrupt. Disassemble TEKDOS from the image (`build/dasm s2650 <(dd if=IMG bs=1 skip=$((0x1000)) count=$((0x4000))) 0 START COUNT`: image offset 0x1000 is memory 0000). Check against the ztpe.nl OS reference (`sources/ztpe/osinternals.txt`, Annex B ports, chapter 8 debugging), which covers the same hardware under Signetics' DOS versions.

**Debug switches** (stderr): `-io` or `TEK_IOTRACE` (ports, and a slave's unmapped I/O), `TEK_EPTRACE` (slave forced jumps, debug interrupts, emulator firmware calls with their blocks), `-fdutrace` or `TEK_FDCTRACE` (every disc strobe and byte; under `-fdc hle`, sector reads and writes), `TEK_INTTRACE` (interrupts taken), `-trace FILE` (2650 instructions).

## Build and smoke test
```
cd emu && make                                    # seconds; no dependencies
build/tek8002 -0 ../disks/TekDOS_3.3_6800_cpy1.img   # TEKDOS prompt after ~5 s; Ctrl-] then q quits
```
Batch run, no terminal needed (stdin not a terminal: runs flat out, about 50× real time):
```
build/tek8002 -0 ../disks/TekDOS_3.3_6800_cpy1.img -cycles $((25*1250000)) -type 6 'LDIR\r' </dev/null
```
`-cycles` counts 2650 clocks at 1.25 MHz, so 1,250,000 is one emulated second. `-type T TEXT` types at emulated second T. `-0`…`-3` mount images in drives 0–3; `-rw` makes them writable and saves them on exit. Discs are raw images of 315,392 bytes in logical sector order.

## Regression checks (run after touching CPU cores or machine code)
1. `make -C emu test` must pass: the Debug module's and disc controller's unit tests, `tests/boot_ldir.sh` (boot and LDIR of two discs, both disc models) `tests/asm_link.sh` (both) and `tests/run6800.sh`, `tests/runz80.sh` and `tests/prototype.sh` (the boards, DEBUG, modes 1/2; run the first two with `FDC=hle` too after Debug-module changes); `tests/syscomm.sh` after System Communications changes, and `tests/disc_tools.sh` (with and without `FDC=hle`) after disc-unit changes; `tests/dip.sh` (the 8002 diagnostics' modules the emulator passes, `notes/diagnostics.md`). After controller or drive changes, also LDIR every disc in `sources/bitsavers/disks` with `-fdc hle` and the default and compare.
2. After disc-unit changes, `../tekmato/scripts/regression.sh` must pass: its section 6 runs TEKDOS's FORMAT, COPY and DELETE in this emulator.
3. **GUI (if SDL3 is installed):** `make gui`, then `SDL_VIDEODRIVER=dummy SDL_RENDER_DRIVER=software build/tek8002-gui -0 IMG -cycles $((40*1250000)) -type prompt 'LDIR\r' -shot 35 x.bmp` must show the LDIR listing (and `x_8002a.bmp`, `x_fdu.bmp` the panels).
4. **Screenshots:** `tools/make_screenshots.sh` (and `make_hero.sh`, `make_tutorial_shots.sh` after GUI or panel changes, `make_rtpa_shots.sh` after RTPA or 8080-board changes) regenerates `docs/screenshots/`; `git status docs/` must stay clean unless a visual change was intended.
5. More checks are added here as each step lands, each with a known-good reference: a printout, a manual's sample session, or a real machine.

## Conventions (shared with ../tektronix-8550-emulator)
- **Minimal edits to ported cores:** keep every change small and mark it (`[tek8550]` marks MDL's; this project's use `[tek8002]`). Record core modifications in `emu/src/cpu/SOURCE.txt`. A fix to a shared core goes to MDL as well.
- **Machine code mirrors MAME devices:** one class per board, each decoding its own ports (`tek8002_debug::decodes`). No board is special-cased in the mainframe: slaves (Assembler Processor, emulator boards) will be self-contained boards behind one interface, as MDL's `emulator_board`.
- **Facts go into `notes/*.md`**, each with how it was established (manual section, ROM or TEKDOS address, the run that showed it). Label inferred behaviour as inferred. Add a `CHANGELOG.md` entry at milestones and keep `ROADMAP.md` current.
- **Fidelity:** model what the 1979 hardware did, backed by manuals or the original software. Interfaces to the outside (future prototype links) carry only real pin information, as MDL's prototype link v3.
- **Untrusted material:** downloaded files and extracted archives go in their own new directory. Run Python that reads them with `python3 -I`. Original images in `sources/` are never written: copy an image into `disks/` before mounting it with `-rw`.
- **Downloads:** bitsavers material goes in `sources/bitsavers/` (bitsavers.org refuses scripted access; `https://bitsavers.mirrorservice.org/` mirrors it), manuals with `pdftotext -layout` text next to them. Make PDFs read-only. Large scans and photos are git-ignored (re-downloadable).
- **Licence and authorship:** original files start with `SPDX-License-Identifier: GPL-2.0-or-later` and `Copyright (C) 2026 Hugo José Pinto <hugo.pinto@gmail.com>` (comment syntax of the file; generators emit it into their output). Ported files keep their own headers. See `NOTICE.md`.
- **No AI attribution in this project's own commits.** Commits, commit messages, tags and release notes carry no AI attribution: no `Co-Authored-By` trailers naming an AI, no "Generated with" lines, no session links. All work is authored by Hugo José Pinto. `.claude/settings.json` sets Claude Code's `attribution` to empty. Contributors may use whatever tools they like; their pull requests are not checked for it.
- **Commits:** commit when asked; a local commit at each finished, regression-checked milestone is authorised. There is no remote yet: push nothing until the user creates one and asks.
- **No personal paths** (`/Users/...`) in tracked files.
